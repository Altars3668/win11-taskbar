## 方片轨迹的验证边界

用户报告的现象不是普通退场动画：指针移动后方片留在原位，只有点击才消失；还可能沿轨迹逐片移动、循环出现。

原实现使用 `Shell.BlurEffect(BACKGROUND)`，从当前 framebuffer 复制采样区域。在局部重绘和缓冲区复用的情况下，自身悬停反馈可能进入后续采样。修正实现用独立场景：仅克隆壁纸和可见应用窗口，按叠放顺序排列，用 ACTOR 模式离屏模糊，再叠加色调和噪点。模糊纹理整体做圆角裁剪；阴影不参与采样。

这避免了自身 UI 的回采路径，但不能仅凭截图或录屏宣布真实显示器的问题已经消失。录屏可能改变重绘条件。隔离 headless Shell 的新实现通过了快速划过前后静态像素比较、应用窗口内容变化采样、反复启停及静止开销检查；同一场景下旧版也没有重现方片轨迹，所以它不是证明真实硬件症状已修复的成功 A/B。

真实桌面上的进一步验证应保持“移动 → 停住、不点击 → 再点击”顺序，并区分旧 framebuffer 的重复采样、阴影损坏区域和其它模糊扩展的影响。不可把永久关闭全局 clipped redraw 当作默认修复，它会增加 GPU 开销。

## 2026-10-04 菜单刷新故障与恢复边界

真实 DBusMenu 可能在 AboutToShow 后发出 LayoutUpdated。旧宿主把该信号再接到 AboutToShow，形成请求风暴。修正后信号只触发去抖的 GetLayout，限制在途请求并检查 revision；`tools/test-dbusmenu-storm.py` 用会发此信号的程序验证请求有界。

故障恢复中，主代理错误地用 gdb 调用运行中 GJS 的 eval，触发 SIGSEGV，导致真实 Wayland 图形会话退出。不能使用这条恢复路径，也不能把原窗口已丢失说成“无损重载”。禁止在运行中 GJS 上下文通过调试器执行 JS；卡死时停止自动输入，只做只读诊断并保留需要用户批准的会话重启门。

## 不注销的加载限制

GNOME 50 的普通 disable/enable 不会刷新已导入的 ES module，`ReloadExtension` 已明确弃用。磁盘源码变化和真实会话已经运行新代码不是同一件事。

诊断时可以通过用户自己的 Looking Glass 做窄范围、可撤销的会话内材质替换，保留已注册的按钮类型和客户端窗口；应先在旧版隔离 Shell 中验证替换与还原。不得为此启用 unsafe-mode、操作剪贴板内容或修改全局重绘优化。完整功能更新由正常的下一次登录加载，不在未授权时注销用户。
